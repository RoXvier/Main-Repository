# 3.5.8-folderglass-debug.1 — grey/yellow One UI folder glass

Debug build on top of stable 3.5.8. Release behaviour is unchanged unless the new
experiment is switched on.

## Symptom

With a custom Duo wallpaper, semi-transparent One UI Home folders (including large
3×3 folders) keep the frosted look of Samsung's grey/yellow Fold 8 default wallpaper.
Only a fully transparent folder background hides it.

## Cause

- Hinge angles come from Samsung's `FoldInteractive` live wallpaper, so
  `WallpaperSetupService` keeps it bound to both HOME slots (5 and 17, `video_001.mp4`).
  Duo never replaces it; `LockPhotoApplier` writes lock slots only.
- The custom photo is Duo's own compositor surfaces (`NativePhotoLayer` in the
  below-app wallpaper area, `HomePhotoLayer` under the launcher window). They sit beside
  Samsung's wallpaper window, not inside it.
- Wallpaper-derived effects read the system wallpaper itself. In AOSP,
  `WallpaperController.screenshotWallpaperLocked()` captures only the wallpaper window and
  `mirrorWallpaperSurface()` mirrors only the wallpaper token. A frosted folder built from
  either source cannot contain Duo's photo, so it shows the hidden grey/yellow wallpaper.
  A normal compositor blur of what is on screen would show the photo, and the visible
  result rules that out.

Which wallpaper-only source One UI uses is not public. The debug screen measures it.

## Debug screen

Launcher entry **Duo 資料夾 Debug**, or Custom wallpaper → Advanced Settings →
**Folder glass debug**.

1. **Diagnosis / A/B test.** After 6 s (time to go Home), the Shizuku/root helper records
   launcher version, `dumpsys wallpaper`, SurfaceFlinger blur lines and layer names, and the
   window list. It takes a screenshot, sets `cmd wallpaper dim-with-uid 2000 1`, waits 3 s,
   takes another, then restores the previous value. The app compares the two screenshots on
   the phone. Red pixels in `folder-glass-diff.png` changed even though only the hidden
   Samsung wallpaper was dimmed, which means those pixels come from the system wallpaper.
   Raw screenshots are deleted after comparison.
2. **Fix (experimental).** It saves a strength (70/85/100 %) in `files/folder-glass-dim.txt`.
   While the custom wallpaper host runs, `PhotoInstrumentation` applies
   `dim-with-uid 2000 <strength>` to Samsung's hidden wallpaper. It clears the value when the
   host stops, when custom wallpaper is disabled, and once at every host start.
   Expected result: folders show a neutral dark translucent glass instead of grey/yellow.
   Unlock flashes of the underlying wallpaper become dark instead of grey/yellow.
3. **Share.** Shares the report and the comparison image through the existing FileProvider.

## Limits and checks

- Dimming cannot put the *photo* into One UI's glass, because that glass ignores Duo's
  surfaces. The fix only neutralises the wrong colour.
- AOSP applies the dim amount to every active wallpaper engine. Check the lock screen
  after enabling. If your lock photo turns dark, turn the fix off.
- Android persists the dim amount. If the phone reboots before Shizuku restarts, the
  Samsung wallpaper may look dark until Duo's host runs again (it then re-syncs).
  Before uninstalling this build, press "關閉修正並還原", or run:
  `adb shell cmd wallpaper dim-with-uid 2000 0`
- If the A/B test reports `dimAccepted=false`, this firmware does not support the AOSP
  wallpaper dim shell command, and the fix cannot work.

## Build

`./gradlew assembleGithubDebug`, or run the **Folder glass debug APK** workflow
(workflow_dispatch) in a fork. Debug builds are signed with the committed, intentionally
public `app/folderglass-debug.keystore`, so later debug builds update in place. They cannot
replace the official signed release. Uninstall the official app first (this removes its
settings and saved photos), and uninstall this build before going back.

Changed files: `FolderGlass*.java` (new), `PhotoInstrumentation.java`, `RootHelpers.java`,
`AndroidManifest.xml`, `WallpaperStudioActivity.kt` (one button), `app/build.gradle.kts`
(debug suffix/signing), `.github/workflows/folder-glass-debug.yml`, unit tests.
